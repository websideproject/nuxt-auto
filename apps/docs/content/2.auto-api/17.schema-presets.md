# Schema Presets (Cross-engine)

nuxt-auto-api ships **per-dialect column preset** helpers so every table gets `timestamps`, `softDelete`, `tenant`, `id`, `audit`, and `json` columns with one import — and because auto-api's features are **convention-driven** (detect `deletedAt` by name; `updatedAt` self-manages via drizzle `$onUpdate`), *importing a preset activates the feature automatically*. No extra config.

## Why per-dialect

Drizzle has no cross-dialect column abstraction: `integer` comes from `sqlite-core`, `timestamp`/`jsonb` from `pg-core`, `datetime`/`json` from `mysql-core`. Presets are thin **per-dialect modules** behind three subpath exports — exactly how you already choose `sqliteTable` vs `pgTable`.

| Engine | Import subpath |
|---|---|
| `better-sqlite3` / D1 / Turso | `@websideproject/nuxt-auto-api/schema/sqlite` |
| Postgres | `@websideproject/nuxt-auto-api/schema/pg` |
| MySQL / PlanetScale | `@websideproject/nuxt-auto-api/schema/mysql` |

## Usage (SQLite example)

```ts
import { sqliteTable, text } from 'drizzle-orm/sqlite-core'
import { id, timestamps, tenant, softDelete, audit, liveUnique, json } from '@websideproject/nuxt-auto-api/schema/sqlite'

const sd = softDelete()   // { columns, indexes(t) }

export const articles = sqliteTable('articles', {
  ...id(),                  // uuid text PK
  title: text('title').notNull(),
  slug: text('slug').notNull(),
  ...tenant(),              // organizationId text
  ...timestamps(),          // createdAt + updatedAt (self-managing)
  ...audit(),               // createdBy + updatedBy (filled by audit-stamp plugin)
  ...sd.columns,            // deletedAt, deletedBy, deletionId, deletedReason
}, t => [
  ...sd.indexes(t),         // articles_trash_idx (deletedAt) + articles_batch_idx (deletionId)
  ...tenant.indexes(t),     // articles_tenant_org_idx
  liveUnique(t, t.slug, 'articles_slug_live'),  // partial unique among live rows
])
```

Postgres and MySQL are identical except the import path.

## Preset reference

| Preset | Returns | Auto-activates |
|---|---|---|
| `id(opts?)` | `{ id }` UUID PK — `id({ mode: 'serial' })` for an auto-increment integer | — |
| `timestamps()` | `{ createdAt, updatedAt }` | `updatedAt` self-updates via `$onUpdate` |
| `audit()` | `{ createdBy, updatedBy }` | Filled by the built-in **audit-stamp plugin** (see below) |
| `tenant(opts?)` | `{ organizationId }` (or `{ [opts.field] }`) + `tenant.indexes(t, opts?)` | Tenant scoping (if multiTenancy configured). With a custom `field`, pass it to the index too: `tenant.indexes(t, { field: 'workspaceId' })` |
| `softDelete(opts?)` | `{ columns, indexes(t) }` | Full soft-delete pipeline (list hide, restore, purge, cascade) |
| `json(name)` | Dialect-correct JSON column | — |
| `liveUnique(t, col, name)` | Unique index among live rows (partial; on MySQL over `liveUniqueMysql()`'s column) | Prevents unique-collision on deleted rows |

### `softDelete()` options

```ts
softDelete({
  by:     true,   // include deletedBy (userId who trashed). default: true
  batch:  true,   // include deletionId (batch restore/purge). default: true
  reason: true,   // include deletedReason. default: true
})
```

### Index naming

`softDelete().indexes(t)` and `tenant.indexes(t)` **auto-namespace** their index names with the
owning table (e.g. `articles_trash_idx`, `articles_batch_idx`, `articles_tenant_org_idx`; with a custom tenant
field, `articles_tenant_workspace_id_idx`). This is
required because SQLite and Postgres index names must be **globally unique** within a database — a
fixed `trash_idx` would collide the moment a second table adopts the preset. The table name is read
from the column inside the index callback, so you don't pass it yourself.

## Cross-engine differences

| Concern | SQLite | Postgres | MySQL |
|---|---|---|---|
| UUID PK | `text` + `$defaultFn` | `uuid().defaultRandom()` | `varchar(36)` + `$defaultFn` |
| Serial PK (`id({ mode: 'serial' })`) | `integer` autoincrement | `serial` | `int auto_increment` |
| Timestamp | `integer(mode:'timestamp')` | `timestamp({withTimezone})` | `datetime` |
| JSON | `text(mode:'json')` | `jsonb` | `json` |
| Partial unique (`liveUnique`) | ✅ `WHERE` clause | ✅ `WHERE` clause | ✅ generated column (`liveUniqueMysql()`) |

### MySQL `liveUnique`

MySQL has no filtered indexes. `liveUniqueMysql('slug')` adds a stored generated column, `slug_live` (property
`slugLive`), that holds the value while the row is live and `NULL` once it is trashed; MySQL unique indexes ignore
`NULL`, so `liveUnique` on that column is unique among live rows only. drizzle-kit generates both:

```ts
import { mysqlTable, varchar } from 'drizzle-orm/mysql-core'
import { id, softDelete, tenant, liveUnique, liveUniqueMysql } from '@websideproject/nuxt-auto-api/schema/mysql'

const sd = softDelete()
export const articles = mysqlTable('articles', {
  ...id(),
  ...tenant(),
  slug: varchar('slug', { length: 255 }).notNull(),
  ...sd.columns,
  ...liveUniqueMysql('slug'),                  // slugLive: varchar(255) generated always as (…) stored
}, t => [
  ...sd.indexes(t),
  liveUnique(t, t.slugLive, 'articles_slug_live'),
  // or per tenant: liveUnique(t, [t.organizationId, t.slugLive], 'articles_org_slug_live')
])
```

The argument is the column's SQL name; `{ length }` sets the generated column's varchar length (default 255).
On MySQL `liveUnique` refuses columns that are not generated — a plain unique index would make trashed rows
collide too.

## The audit-stamp plugin

`createdBy` / `updatedBy` are server-owned: request bodies can never set them. They are filled by the built-in
audit-stamp plugin, which is **on by default** — there is nothing to register. To turn it off:

```ts
// nuxt.config.ts
autoApi: {
  auditStamps: false,
}
```

- `createdBy` is set on **create** (null for system/task writes).
- `updatedBy` is overwritten on every **create + update** (client-supplied value is ignored).
- Raw drizzle writes (privacy erasure, migrations) bypass it — intended.
- Tables without the columns are unaffected.

Without the plugin the columns stay `NULL`.

## "Import = feature on" principle

| Add this preset | Gets this auto-api behavior |
|---|---|
| `...timestamps()` | `updatedAt` auto-refreshes on every update |
| `...softDelete()` | List hides deleted, restore route, purge/trash, cascade |
| `...tenant()` | Tenant scoping when `multiTenancy` is configured |
| `...audit()` | `createdBy`/`updatedBy` stamped from request user |
