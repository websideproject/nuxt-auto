# Database Adapters

@websideproject/nuxt-auto-api supports multiple database engines through a unified adapter layer. Each adapter normalizes engine-specific behavior like transactions, batch operations, and mutation count parsing.

## Supported Engines

| Engine | Package | `atomic()` | Returning | Native Batch |
|--------|---------|-------------|-----------|-------------|
| `better-sqlite3` | `better-sqlite3` | transaction (`BEGIN IMMEDIATE`) | Yes | No |
| `postgres` | `pg` / `postgres` | `db.transaction()` | Yes | No |
| `mysql` | `mysql2` | `db.transaction()` | No — rows are read back | No |
| `d1` | Cloudflare D1 | **not a transaction** (see below) | Yes | Yes |
| `turso` | `@libsql/client` | `db.transaction()` | Yes | Yes |
| `planetscale` | `@planetscale/database` | `db.transaction()` | No — rows are read back | No |

On engines without `RETURNING` (MySQL, PlanetScale) the create/update routes insert or update, then select the
row by primary key, so responses are the same on every engine. Use `insertReturning` / `updateReturning` in
your own endpoints for the same behaviour.

::callout{icon="i-lucide-triangle-alert"}
**D1 has no interactive transactions** — only `db.batch()` of prepared statements, which an arbitrary async
function cannot use. On D1, `atomic()` runs the function directly and `adapter.supportsTransactions` is
`false`: writes made before an error stay. Transactional bulk requests therefore stop at the first failing item
and report how many items before it were written (`data.committed`) instead of claiming a rollback; M2M sync
and cascade soft delete are likewise not atomic on D1.
::

## Setup

### Using `initializeDatabase`

Initialize the database with `initializeDatabase()` in a server plugin:

```typescript
// server/plugins/database.ts
import { drizzle } from 'drizzle-orm/better-sqlite3'
import Database from 'better-sqlite3'
import { initializeDatabase } from '@websideproject/nuxt-auto-api/database'
import * as schema from '../database/schema'

export default defineNitroPlugin(() => {
  const sqlite = new Database('sqlite.db')
  const db = drizzle(sqlite, { schema })

  initializeDatabase(db, 'better-sqlite3')
})
```

### Postgres

```typescript
import { drizzle } from 'drizzle-orm/node-postgres'
import { Pool } from 'pg'
import { initializeDatabase } from '@websideproject/nuxt-auto-api/database'

export default defineNitroPlugin(() => {
  const pool = new Pool({ connectionString: process.env.DATABASE_URL })
  const db = drizzle(pool, { schema })

  initializeDatabase(db, 'postgres')
})
```

### Cloudflare D1

```typescript
import { drizzle } from 'drizzle-orm/d1'
import { initializeDatabase } from '@websideproject/nuxt-auto-api/database'

export default defineNitroPlugin(() => {
  const db = drizzle(env.DB, { schema })

  initializeDatabase(db, 'd1')
})
```

### Turso / LibSQL

```typescript
import { drizzle } from 'drizzle-orm/libsql'
import { createClient } from '@libsql/client'
import { initializeDatabase } from '@websideproject/nuxt-auto-api/database'

export default defineNitroPlugin(() => {
  const client = createClient({
    url: process.env.TURSO_DATABASE_URL!,
    authToken: process.env.TURSO_AUTH_TOKEN,
  })
  const db = drizzle(client, { schema })

  initializeDatabase(db, 'turso')
})
```

## Configuration

The engine is the second argument of `initializeDatabase(db, engine)` — that is the only place it is set. The
`autoApi.database` module option is not read (it is kept only so older configs still type-check).

## Using the Adapter Directly

The adapter is available in `HandlerContext` and from the `getDatabaseAdapter()` helper:

```typescript
import { getDatabaseAdapter } from '@websideproject/nuxt-auto-api/database'

// In a server handler
const adapter = getDatabaseAdapter()

// Run atomic operations (transaction or batch depending on engine)
const result = await adapter.atomic(async ({ tx }) => {
  await tx.insert(users).values({ name: 'Alice' })
  await tx.insert(posts).values({ title: 'Hello', userId: 1 })
  return 'done'
})

// Insert and get the row back on every engine
const [created] = await insertReturning(adapter.db, users, data)

// Parse mutation counts
const result = await db.delete(posts).where(eq(posts.draft, true))
const deleted = adapter.getMutationCount(result)
```

## Adapter API

```typescript
interface DatabaseAdapter {
  engine: DatabaseEngine       // Engine identifier
  db: any                      // Drizzle database instance
  atomic<T>(fn): Promise<T>    // Run operations atomically
  getMutationCount(result): number  // Parse affected rows
  supportsReturning: boolean   // Does the engine support RETURNING?
  supportsNativeBatch: boolean // Does the engine have batch()? (D1, Turso)
  supportsTransactions: boolean // Is atomic() rolled back on error? (false on D1)
}
```

## Legacy `globalThis.__autoApiDb`

Setting `globalThis.__autoApiDb` still works: it is wrapped in a `better-sqlite3` adapter with a deprecation
warning. Switch to `initializeDatabase()`, which also tells the adapter which engine it talks to.

```typescript
// Legacy (still works, deprecated)
globalThis.__autoApiDb = db

// Recommended
initializeDatabase(db, 'better-sqlite3')
```
