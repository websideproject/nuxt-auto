# Form Fields & Widgets

Customize create and edit forms with the admin's widgets: `TextInput`, `TextareaInput`, `NumberInput`,
`CheckboxInput`, `SelectInput`, `DateTimePicker`, `PasswordInput`, `RelationSelect`, `MultiRelationSelect`,
`SlugInput`, `RichTextEditor`, `MarkdownEditor`, `CodeEditor`, `JsonEditor`, `ColorPicker`, `TagsInput`,
`FileUpload` and `ImageUpload`.
An unknown widget name falls back to `TextInput` (with a console warning).

Form fields are configured in `nuxt.config`, which is serialized to JSON on its way to the app: values must be
data. The functions a field can take — `condition` and `validation` — go in `admin.fields.ts` (see
[Field rules](#field-rules)).

## Field Configuration

Each form field is configured with:

```typescript
{
  name: 'fieldName',           // Required: Schema column name
  label: 'Display Label',      // Optional: Shown above field
  widget: 'TextInput',         // Optional: Widget type (auto-detected if omitted)
  required: true,              // Optional: Validation
  readonly: false,             // Optional: Make field non-editable
  placeholder: 'Enter value',  // Optional: Placeholder text
  help: 'Helper text',         // Optional: Shown below field
  options: { /* ... */ },      // Optional: Widget-specific options
}
```

Validation is the API's (see [Validation](/auto-api/validation)): a refused save shows each issue under its field,
and the API's message above the form.

## Available Widgets

### TextInput

Basic single-line text input:

```typescript
{
  name: 'title',
  widget: 'TextInput',
  placeholder: 'Enter title',
  options: {
    minLength: 3,   // optional — checked on submit ("At least 3 characters")
    maxLength: 100, // optional — the input stops at 100 characters
  },
}
```

`minLength` / `maxLength` work on `TextInput`, `TextareaInput` and `PasswordInput`.

### NumberInput

Numeric input with optional constraints:

```typescript
{
  name: 'price',
  widget: 'NumberInput',
  options: {
    min: 0,
    max: 10000,
    step: 0.01,  // For decimals
  },
}
```

### TextareaInput

Multi-line text input:

```typescript
{
  name: 'description',
  widget: 'TextareaInput',
  options: {
    rows: 5, // default 4
  },
}
```

### CheckboxInput

Boolean checkbox:

```typescript
{
  name: 'published',
  widget: 'CheckboxInput',
  label: 'Publish immediately',
}
```

### SelectInput

Dropdown select with predefined options:

```typescript
{
  name: 'status',
  widget: 'SelectInput',
  options: {
    enumValues: ['draft', 'published', 'archived'],
  },
}
```

Or with custom labels:

```typescript
{
  name: 'role',
  widget: 'SelectInput',
  options: {
    options: [
      { label: 'Administrator', value: 'admin' },
      { label: 'Editor', value: 'editor' },
      { label: 'Viewer', value: 'viewer' },
    ],
  },
}
```

### DateTimePicker

Date and/or time picker:

```typescript
{
  name: 'publishedAt',
  widget: 'DateTimePicker',
  options: {
    showTime: true,      // Include time picker (default false)
  },
}
```

With `format`, the field is a text input in that pattern — `YYYY`, `MM`, `DD`, `HH` (24-hour), `mm`, `ss` and any
literal text. Typed text is read when the field loses focus (or on Enter); text that does not match, or is not a real
date, is marked and not saved. The calendar button still picks the date:

```typescript
{
  name: 'publishedAt',
  widget: 'DateTimePicker',
  options: {
    format: 'DD/MM/YYYY HH:mm', // time shown when the pattern has one (showTime overrides)
  },
}
```

For date only:

```typescript
{
  name: 'birthDate',
  widget: 'DateTimePicker',
  options: {
    showTime: false,
  },
}
```

### PasswordInput

Password input with masked characters:

```typescript
{
  name: 'password',
  widget: 'PasswordInput',
  required: true,
}
```

### RelationSelect

Select a related resource (foreign key):

```typescript
{
  name: 'authorId',
  label: 'Author',
  widget: 'RelationSelect',
  options: {
    resource: 'users',         // Related resource name
    displayField: 'name',      // Field to show in dropdown
    searchFields: ['name', 'email'], // Fields to search (optional, default displayField) — a row matching any of them
  },
}
```

Features:
- Async loading of related resources
- Searchable dropdown with debouncing
- Displays current selection even if not in search results

### MultiRelationSelect

Select multiple related resources (M2M relationships):

```typescript
{
  name: 'tags',
  label: 'Tags',
  widget: 'MultiRelationSelect',
  options: {
    resource: 'tags',
    displayField: 'name',
    junctionTable: 'postTags',
    junctionLeftKey: 'postId',
    junctionRightKey: 'tagId',
  },
}
```

**Important:** M2M fields should only be used in edit forms, not create forms. See [M2M Relationships](/auto-admin/m2m-relationships).

### SlugInput

A slug that follows another field while it is empty (or still the generated value): typing your own stops that,
and the button regenerates it. Input is turned into lowercase words joined by dashes.

```typescript
{
  name: 'slug',
  widget: 'SlugInput',
  options: {
    generateFrom: 'title',
  },
}
```

### RichTextEditor / MarkdownEditor

A Nuxt UI editor (`UEditor`) that stores HTML (`RichTextEditor`) or Markdown (`MarkdownEditor`). `toolbar` picks
the buttons, in order, with `'|'` between groups: `bold`, `italic`, `underline`, `strike`, `code`, `heading1`–`3`,
`bulletList`, `orderedList`, `blockquote`, `codeBlock`, `horizontalRule`, `link`, `undo`, `redo`.

```typescript
{
  name: 'content',
  widget: 'MarkdownEditor',
  options: {
    toolbar: ['bold', 'italic', '|', 'heading2', 'bulletList', 'link'], // default: most of them
  },
}
```

The editor needs `@nuxt/ui` 4.3 or later; with an older version the field is a plain textarea (and the console says
why).

### CodeEditor

A monospace editor: Tab indents instead of leaving the field. `language` is shown as a label (there is no syntax
highlighting) and `theme: 'dark'` gives it dark colours.

```typescript
{
  name: 'snippet',
  widget: 'CodeEditor',
  options: { language: 'ts', theme: 'dark', rows: 12 },
}
```

### JsonEditor

Edits a JSON column as pretty-printed JSON. The value is saved only while the text parses; otherwise the field says
what is wrong. JSON columns get it automatically.

```typescript
{
  name: 'settings',
  widget: 'JsonEditor',
  options: { rows: 10 },
}
```

### ColorPicker

A color text field with a picker; stores `#rrggbb` by default (`format: 'rgb' | 'hsl'` for the picker's output).

```typescript
{
  name: 'color',
  widget: 'ColorPicker',
}
```

### TagsInput

A list of tags (Enter, paste or leaving the field adds one). Stored as an array — use a JSON column — or, with
`storeAs: 'string'`, comma-separated in a text column.

```typescript
{
  name: 'keywords',
  widget: 'TagsInput',
  options: { max: 10 },
}
```

### FileUpload / ImageUpload

Upload a file to the record through [`createFileUploadPlugin`](/auto-api/plugin-catalog)'s route
(`POST /api/{resource}/:id/upload`), which stores the file and writes its URL into the column configured for the
resource. `ImageUpload` shows a preview and accepts images by default (the app serves the files — with
`storage: 'local'` they are saved under `server/uploads` and linked as `/uploads/…`). The record must exist, so the field offers
the upload on the edit form (the create form says to save first); the trash button removes the file.

```typescript
{
  name: 'coverImage',     // the column the plugin is configured with for this resource
  widget: 'ImageUpload',
  options: {
    accept: 'image/png,image/jpeg', // file picker filter
    maxSize: '2mb',                 // checked before uploading (the plugin enforces its own maxSize)
  },
}
```

The plugin stores one file per record, so `multiple` is not supported.

## Widget Auto-Detection

If you don't specify a widget, it's auto-detected from the schema:

| Column | Auto Widget |
|------------|-------------|
| Foreign key | RelationSelect |
| Enum column | SelectInput |
| Name contains `password` | PasswordInput |
| `boolean`, or `integer` named `is…` | CheckboxInput |
| `integer` / numeric | NumberInput |
| Timestamp / date, or a name ending in `At` / `Date` | DateTimePicker |
| `text` column, or a name containing `description`, `content`, `body`, `bio`, `notes` | TextareaInput |
| JSON column | JsonEditor |
| Anything else | TextInput |

The first matching row wins. Generated forms leave out the primary key, `createdAt`, `updatedAt` and `deletedAt`.

## Field Validation

`required: true` marks the field and blocks an empty submit ("This field is required" under the field);
`minLength` / `maxLength` are checked the same way. Every other rule comes from the API: the resource's
[validation schemas](/auto-api/validation) run on submit, and when a save is refused each issue is shown under its
field, with the API's message (and issues on fields the form does not show) above the form.

## Field Rules

`condition` (show the field only while it returns true) and `validation` (checked on submit) are functions, so they
live in an app file that is bundled with the admin, `admin.fields.ts` in your source directory (`app/` in Nuxt 4),
or the file `autoAdmin.fields` names:

```typescript
// app/admin.fields.ts
export default defineAdminFields({
  articles: {
    // Shown once the article has a title
    content: { condition: form => !!form.title },
    // An error message (or false) refuses the value; true or nothing accepts it. May be async.
    slug: {
      validation: value => /^[a-z0-9-]+$/.test(String(value ?? '')) || 'Lowercase letters, digits and dashes',
    },
  },
})
```

The rules apply to the field of that name in both forms, generated or configured. `validation` runs after
`required`, before the request; the API's own validation still runs on save. A field hidden by its `condition`
keeps its value.

## Field Layout

Fields are displayed vertically in the order specified. For complex layouts, you can group related fields:

```typescript
formFields: {
  create: [
    // Basic Info
    { name: 'title', widget: 'TextInput', required: true },
    { name: 'slug', widget: 'TextInput', required: true },

    // Content
    { name: 'excerpt', widget: 'TextareaInput' },
    { name: 'content', widget: 'TextareaInput', options: { rows: 12 } },

    // Publishing
    { name: 'status', widget: 'SelectInput' },
    { name: 'publishedAt', widget: 'DateTimePicker' },
    { name: 'authorId', widget: 'RelationSelect' },
  ],
}
```

## Complete Example

```typescript
resources: {
  posts: {
    formFields: {
      create: [
        {
          name: 'title',
          label: 'Post Title',
          widget: 'TextInput',
          required: true,
          placeholder: 'Enter a catchy title',
          help: 'This will be displayed as the main heading',
        },
        {
          name: 'slug',
          label: 'URL Slug',
          widget: 'TextInput',
          required: true,
        },
        {
          name: 'excerpt',
          label: 'Excerpt',
          widget: 'TextareaInput',
          placeholder: 'Brief summary...',
          options: {
            rows: 3,
          },
        },
        {
          name: 'content',
          label: 'Content',
          widget: 'TextareaInput',
          required: true,
          options: {
            rows: 12,
          },
        },
        {
          name: 'authorId',
          label: 'Author',
          widget: 'RelationSelect',
          required: true,
          options: {
            resource: 'users',
            displayField: 'name',
          },
        },
        {
          name: 'status',
          label: 'Status',
          widget: 'SelectInput',
          options: {
            enumValues: ['draft', 'published', 'archived'],
          },
        },
        {
          name: 'publishedAt',
          label: 'Publish Date',
          widget: 'DateTimePicker',
          options: {
            showTime: true,
          },
        },
        {
          name: 'featured',
          label: 'Featured Post',
          widget: 'CheckboxInput',
        },
      ],
      edit: [
        // Same as create, plus M2M relations
        // ... all create fields ...
        {
          name: 'tags',
          label: 'Tags',
          widget: 'MultiRelationSelect',
          options: {
            resource: 'tags',
            displayField: 'name',
            junctionTable: 'postTags',
            junctionLeftKey: 'postId',
            junctionRightKey: 'tagId',
          },
        },
      ],
    },
  },
}
```
