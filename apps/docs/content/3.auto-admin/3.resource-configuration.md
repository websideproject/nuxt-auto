# Resource Configuration

Configure how each resource appears and behaves in the admin panel.

## Basic Configuration

Resources are configured in the `autoAdmin.resources` object:

```typescript
export default defineNuxtConfig({
  autoAdmin: {
    resources: {
      users: {
        displayName: 'Users',
        icon: 'i-heroicons-user-group',
        group: 'User Management',
        order: 1,
      },
      posts: {
        displayName: 'Blog Posts',
        icon: 'i-heroicons-document-text',
        group: 'Content',
        order: 2,
      },
    },
  },
})
```

## Resource Options

### displayName

The human-readable name shown in the UI:

```typescript
resources: {
  users: {
    displayName: 'Users',  // Shown in sidebar, headers, breadcrumbs
  },
}
```

If not specified, the resource name is automatically formatted (`users` → `Users`).

### singularName

One record, for "Create Category", "Edit Category", "Category deleted" and "1 category deleted":

```typescript
resources: {
  people: {
    displayName: 'People',
    singularName: 'Person', // irregular plural: set it
  },
}
```

If not specified, it is derived from `displayName` by English rules (`Categories` → `Category`, `API Keys` →
`API Key`, `Addresses` → `Address`; `Status` stays `Status`).

### icon

Heroicon name for the resource:

```typescript
resources: {
  users: {
    icon: 'i-heroicons-user-group',
  },
  posts: {
    icon: 'i-heroicons-document-text',
  },
  settings: {
    icon: 'i-heroicons-cog-6-tooth',
  },
}
```

Browse available icons at: https://heroicons.com/

If not specified, a default icon is used.

### group

Organize resources into collapsible groups in the sidebar:

```typescript
resources: {
  users: {
    group: 'User Management',
  },
  roles: {
    group: 'User Management',
  },
  posts: {
    group: 'Content',
  },
  pages: {
    group: 'Content',
  },
}
```

Resources without a group appear at the top of the sidebar.

### order

Control the display order within groups (or ungrouped):

```typescript
resources: {
  users: {
    group: 'User Management',
    order: 1,  // Shown first
  },
  roles: {
    group: 'User Management',
    order: 2,  // Shown second
  },
}
```

Lower numbers appear first. If not specified, defaults to 0.

### type

Specify the resource type:

```typescript
resources: {
  users: {
    type: 'resource',  // Default - shows in sidebar with full CRUD
  },
  articleCategories: {
    type: 'junction',  // Hidden from sidebar, managed through M2M relations
  },
}
```

**Types:**
- `'resource'` (default) - Regular resource with full admin UI
- `'junction'` - M2M junction table, hidden from sidebar

### disabled

Temporarily disable a resource without removing its configuration:

```typescript
resources: {
  legacyData: {
    disabled: true,  // Resource exists but is hidden from admin
  },
}
```

## List View Configuration

### listFields

Specify which fields to show in the list table:

```typescript
resources: {
  users: {
    listFields: ['id', 'name', 'email', 'role', 'createdAt'],
  },
}
```

If not specified, up to six columns are picked: the id, a title-like column (`title`, `name`, `email`, …), a
content-like column, a status column (`published`, `status`, …), one foreign key and `publishedAt` or
`createdAt`.

A name that is not a column is a **relation** (a Drizzle `relations()` name): the list includes it with the rows.
`author.name` shows one field of it; `author` alone shows its `name`, `title`, `email` or another label-like field;
a to-many relation (`tags`) lists the first three. The caller needs `read` on the related resource, and an unknown
relation name is the API's 400:

```typescript
resources: {
  posts: {
    listFields: ['id', 'title', 'author.name', 'tags', 'createdAt'],
  },
}
```

Relation columns are shown, not searched, filtered or sorted.

### hiddenFields

Hide fields from all views (list, detail, forms):

```typescript
resources: {
  users: {
    hiddenFields: ['password', 'passwordHash', 'resetToken'],
  },
}
```

Common hidden fields:
- Passwords and sensitive data
- Internal IDs and foreign keys
- System fields like `deletedAt`

Hidden fields include the API's own: a field the API hides (`hiddenFields` on the registration or in
`autoApi`) is hidden in the admin too.

### Read-only fields

List columns in `readonlyFields` to show them read-only in the create and edit forms — generated or configured in
[`formFields`](#form-configuration) — or mark one field read-only there (`readonly: true`). Either way it is shown
in the form and left out of the request.

```typescript
resources: {
  articles: {
    readonlyFields: ['slug'],
  },
}
```

Fields the caller may not write (`fields[x].write`) are made read-only automatically.
Generated edit forms already show foreign-key columns ending in `Id` (except `userId`) read-only.

## Form Configuration

Configure forms for create and edit operations:

```typescript
resources: {
  articles: {
    formFields: {
      create: [
        { name: 'title', widget: 'TextInput', required: true },
        { name: 'slug', widget: 'TextInput', required: true },
        { name: 'content', widget: 'TextareaInput' },
        { name: 'published', widget: 'CheckboxInput' },
      ],
      edit: [
        // Same as create, but you can customize differently
        { name: 'title', widget: 'TextInput', required: true },
        { name: 'slug', widget: 'TextInput', readonly: true },
        { name: 'content', widget: 'TextareaInput' },
        { name: 'published', widget: 'CheckboxInput' },
      ],
    },
  },
}
```

If `formFields` is not specified, the admin panel auto-generates forms from the schema. A mode you configure
replaces its generated form — only the fields you list are shown. `edit` falls back to `create` when it is left
out, and a mode with nothing configured keeps the generated form (so giving only `edit` leaves the create form and
the import dialog generated).

See [Form Fields & Widgets](/auto-admin/form-fields-widgets) for detailed form configuration.

## Complete Example

```typescript
export default defineNuxtConfig({
  autoAdmin: {
    resources: {
      users: {
        displayName: 'Users',
        icon: 'i-heroicons-user-group',
        group: 'User Management',
        order: 1,
        listFields: ['id', 'name', 'email', 'role', 'createdAt'],
        hiddenFields: ['password', 'passwordHash'],
      },

      posts: {
        displayName: 'Blog Posts',
        icon: 'i-heroicons-document-text',
        group: 'Content',
        order: 1,
        listFields: ['id', 'title', 'authorId', 'status', 'publishedAt'],
        formFields: {
          create: [
            { name: 'title', widget: 'TextInput', required: true },
            { name: 'slug', widget: 'TextInput', required: true },
            { name: 'excerpt', widget: 'TextareaInput', options: { rows: 3 } },
            { name: 'content', widget: 'TextareaInput', options: { rows: 12 } },
            { name: 'authorId', widget: 'RelationSelect', label: 'Author',
              options: { resource: 'users', displayField: 'name' } },
            { name: 'status', widget: 'SelectInput',
              options: { enumValues: ['draft', 'published', 'archived'] } },
            { name: 'publishedAt', widget: 'DateTimePicker', options: { showTime: true } },
          ],
          edit: [
            { name: 'title', widget: 'TextInput', required: true },
            { name: 'slug', widget: 'TextInput', readonly: true },
            { name: 'excerpt', widget: 'TextareaInput', options: { rows: 3 } },
            { name: 'content', widget: 'TextareaInput', options: { rows: 12 } },
            { name: 'authorId', widget: 'RelationSelect', label: 'Author',
              options: { resource: 'users', displayField: 'name' } },
            { name: 'status', widget: 'SelectInput',
              options: { enumValues: ['draft', 'published', 'archived'] } },
            { name: 'publishedAt', widget: 'DateTimePicker', options: { showTime: true } },
            // M2M Relations
            {
              name: 'tags',
              label: 'Tags',
              widget: 'MultiRelationSelect',
              options: {
                resource: 'tags',
                displayField: 'name',
                junctionTable: 'postTags',
                junctionLeftKey: 'postId',
                junctionRightKey: 'tagId',
              },
            },
          ],
        },
      },

      comments: {
        displayName: 'Comments',
        icon: 'i-heroicons-chat-bubble-left',
        group: 'Content',
        order: 2,
      },

      // Hide junction tables
      postTags: {
        type: 'junction',
      },
    },
  },
})
```

## Auto-Generation

If you don't configure a resource, the admin panel auto-generates everything:

- **displayName** - Formatted from resource name
- **singularName** - Derived from displayName
- **icon** - Default icon
- **listFields** - Up to six picked columns (see above)
- **formFields** - All editable columns with appropriate widgets

This works great for prototyping, but custom configuration gives you more control.

## Best Practices

1. **Always hide sensitive fields** (passwords, tokens, etc.)
2. **Use meaningful display names** for better UX
3. **Group related resources** for easier navigation
4. **Set appropriate field orders** to match user workflow
5. **Leave system fields out of forms** (id, createdAt, etc. — generated forms already do)
6. **Configure M2M relations** in edit forms only
