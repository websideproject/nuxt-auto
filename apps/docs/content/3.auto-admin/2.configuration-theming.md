# Configuration & Theming

Customize the appearance and behavior of your admin panel.

## Module Options

All configuration goes in the `autoAdmin` key of your `nuxt.config.ts`:

```typescript
export default defineNuxtConfig({
  autoAdmin: {
    prefix: '/admin',
    branding: { /* ... */ },
    permissions: { /* ... */ },
    features: { /* ... */ },
    resources: { /* ... */ },
    customPages: [ /* ... */ ],
    dashboard: { /* ... */ },
  },
})
```

## Branding

Customize the admin panel's visual identity:

```typescript
autoAdmin: {
  branding: {
    // Admin panel title (shown in sidebar and browser tab)
    title: 'My Admin Panel',

    // Logo URL or path (shown in sidebar)
    logo: '/admin-logo.svg',

    // Favicon (optional)
    favicon: '/admin-favicon.ico',
  },
}
```

### Logo Guidelines

- **Size:** Recommended 28x28px for best appearance
- **Format:** SVG, PNG, or any web-compatible image
- **Path:** Relative to `public/` directory or absolute URL
- **Fallback:** If no logo is provided, a default icon is shown

## Prefix

Set the base URL for all admin routes:

```typescript
autoAdmin: {
  prefix: '/admin',  // Default
}
```

All admin pages will be available under this prefix:
- `/admin` - Dashboard
- `/admin/users` - Users list
- `/admin/users/new` - Create user
- `/admin/users/1` - User detail
- `/admin/users/1/edit` - Edit user

## Features

Turn the resource list's tools on or off:

```typescript
autoAdmin: {
  features: {
    search: true,        // Default: true
    filters: true,       // Default: true
    bulkActions: true,   // Default: true
    export: true,        // Default: true
    import: false,       // Default: false
    auditLog: false,     // Default: false
  },
}
```

Every feature goes through nuxt-auto-api's own routes, as the signed-in user: the API authorizes each request,
and the admin only offers what `GET /api/permissions` says the caller may do. A control the caller may not use
is hidden or shown disabled, per [`permissions.unauthorizedButtons`](#permission-behavior). API errors are shown
as the API sends them.

What the admin can use is read from nuxt-auto-api's options at build time: the page and batch limits
(`pagination.maxLimit`, `bulk.maxBatchSize`, `bulk.enabled`) and the routes of the export and audit-log plugins,
when those plugins are listed inline in `nuxt.config` (see
[Plugin Registration](/auto-api/plugin-system#plugin-registration)).

### Search

A search box above the list. The term is matched (`$like`, "contains") against every text column the list
shows, as one `$or`, and combined with the column filters. Typing waits for a pause before the list reloads.

- Only columns in the list's `listFields` that the caller may read are searched — hidden fields and fields
  whose `fields[x].read` rule denies the caller are left out (the API refuses a filter on them with a 400).
- Case sensitivity is the database's: `LIKE` ignores case for ASCII on SQLite and MySQL, not on Postgres.
- The term is kept in the URL (`?q=`), so a searched list can be reloaded or shared.

![The articles list searched for Draft: two rows remain, and the footer reads Showing 1 to 2 results](/screenshots/admin-list-search-1440.png)

### Filters

A **Filters** button opens one filter per list column the caller may read, chosen by the column's type:

| Column | Filter | Sent as |
|---|---|---|
| text | contains | `{ title: { $like: 'nuxt' } }` |
| enum | one value | `{ status: { $eq: 'live' } }` |
| boolean | yes / no | `{ published: { $eq: true } }` |
| number | min / max | `{ views: { $gte: 10, $lte: 100 } }` |
| date / timestamp | from / to (whole days, browser time zone) | `{ createdAt: { $gte: '…Z', $lte: '…Z' } }` |

JSON, blob and UUID columns get no filter. Each filter clears on its own, or all at once; they are kept in the
URL (`?filters=`) together with the page.

![The Filters popover on the articles list: a min/max range for Id, a Contains box for Title, an Any/Yes/No select for Published and a date range for Created At](/screenshots/admin-list-filters-1440.png)

### Bulk actions

Row checkboxes and **Delete selected**, which sends one `DELETE /api/{resource}/bulk { ids }` after a
confirmation.

- **Permission:** `canDelete`. Without it there are no checkboxes, and the button is hidden or disabled.
- Selection is per page and cleared when the page, search or filters change: nothing off-screen is deleted.
- In the default transactional mode a failure deletes nothing, and the dialog names the item that failed
  (`Item 2 (id 17): not found`). With `bulk.transactional: false` the others are deleted and each failure is listed.
- Off when the API's bulk routes are disabled (`autoApi.bulk.enabled: false`).

![Two articles selected and the bulk delete confirmation open: Delete 2 articles? This action cannot be undone](/screenshots/admin-bulk-delete-1440.png)

### Export

**Export → CSV / JSON** downloads the list **as it is currently searched and filtered**, with every field the
caller may read (JSON is an array of rows).

- **Permission:** `canRead`.
- With [`createExportPlugin`](/auto-api/plugin-catalog#data-export-createexportplugin) registered for the resource,
  the file comes from `GET /api/{resource}/export?format=csv|json`, in the formats the plugin allows, up to its
  `maxRows`.
- Without it, the admin pages through `GET /api/{resource}` with the keyset cursor, `pagination.maxLimit` rows at
  a time, up to 10,000 rows, and writes the file in the browser.
- Either way, CSV cells a spreadsheet would run as a formula (starting with `=`, `+`, `-`, `@`, a tab or a CR)
  get a leading `'`. A toast says when the export stopped at the row cap.

![The Export menu on the articles list, offering CSV and JSON](/screenshots/admin-list-export-1440.png)

### Import

**Import** uploads a CSV file (with a header row), maps each of its columns to a field — matched by name or label,
editable — and previews the first rows. The rows are then created with `POST /api/{resource}/bulk { items }`, in
batches of the API's `bulk.maxBatchSize` (default 100), one after the other.

- **Permission:** `canCreate`. Only fields of the create form the caller may write are offered.
- Numbers and booleans (`true`/`false`, `1`/`0`, `yes`/`no`) are typed from the column; an empty cell is left out,
  so the column default applies. Everything else is sent as text for the API to validate.
- Each batch reports how many rows it created, or the rows the API rejected (`Row 137: status: Invalid option`).
  In transactional mode a failed batch writes nothing and the import stops there; the batches before it stay
  created.
- Off by default, and when the API's bulk routes are disabled.

![The import dialog: Import Articles, upload a CSV file, match its columns to fields, then create the records](/screenshots/admin-import-1440.png)

### Audit log

A **History** panel on the record's page (and in the view dialog): the latest 20 changes to the record, newest
first, with who made them and which fields an update changed.

- Needs [`createAuditLogPlugin`](/auto-api/plugin-catalog#audit-log-createauditlogplugin) registered; it reads
  `GET /api/audit-logs?resource=…&recordId=…`, which is authorized by the audit table's own `read` permission.
- Without the plugin there is no panel. A caller who may not read the log gets a one-line note instead, never an
  error page.
- Off by default.

## Permission Behavior

Control how the UI responds to permission restrictions:

```typescript
autoAdmin: {
  permissions: {
    // How to handle buttons when user lacks permission
    // 'disable' = show buttons but disable them (default)
    // 'hide' = completely hide buttons
    unauthorizedButtons: 'disable',

    // How to handle sidebar items when user lacks permission
    // 'hide' = completely hide items from sidebar (default)
    // 'disable' = show items but in disabled state
    unauthorizedSidebarItems: 'hide',
  },
}
```

### Button Behavior Options

**`unauthorizedButtons: 'disable'` (default)**
- Buttons are visible but disabled
- Forms show with all fields disabled
- User sees what they could do with proper permissions
- Better for internal users who might request access

**`unauthorizedButtons: 'hide'`**
- Buttons are completely hidden
- Forms show permission denied message
- Cleaner UI for external users
- Stricter access control

### Sidebar Behavior Options

**`unauthorizedSidebarItems: 'hide'` (default)**
- Resources without permissions don't appear in sidebar
- Cleaner navigation
- Users only see what they can access

**`unauthorizedSidebarItems: 'disable'`**
- Resources without permissions appear grayed out
- Not clickable
- Shows what exists but is restricted
- Better discoverability

See [Permissions](/auto-admin/permissions) for more details.

## Access Control

Decide who may open the admin with a **named route middleware** of your app. It runs on every admin page:

```typescript
// nuxt.config.ts
autoAdmin: {
  middleware: 'admin-only',   // or ['auth', 'admin-only']
}
```

```typescript
// middleware/admin-only.ts
export default defineNuxtRouteMiddleware(async () => {
  const { data } = await useFetch('/api/permissions')
  const canManageAnything = Object.values(data.value?.permissions ?? {}).some(p => p.canUpdate)
  if (!canManageAnything) return navigateTo('/login')
})
```

Inside the admin, every resource page also requires some permission on its resource, and every button reflects
what the API allows the caller (see [Permissions](/auto-admin/permissions)). None of this is what protects your
data — nuxt-auto-api enforces authorization on every request, whatever the UI shows.

::callout{icon="i-lucide-triangle-alert"}
`access: (user) => …` is gone: a function in `nuxt.config` never reaches the running app, so it was never
applied. Setting it now fails the build — move the check into a route middleware.
::

## Theming with Nuxt UI

Since @websideproject/nuxt-auto-admin uses `@nuxt/ui`, you can customize the appearance using Nuxt UI's theming system:

### App Config

```typescript
// app.config.ts
export default defineAppConfig({
  ui: {
    primary: 'blue',
    gray: 'slate',
  },
})
```

### Tailwind Configuration

```typescript
// tailwind.config.ts
import type { Config } from 'tailwindcss'

export default {
  theme: {
    extend: {
      colors: {
        // Your custom colors
      },
    },
  },
} satisfies Config
```

### Color Mode

Dark mode is supported by default through Nuxt UI. Users can toggle between light and dark themes using the color mode switcher.

## Custom CSS

Add custom styles to override or extend the default admin styles:

```typescript
// nuxt.config.ts
export default defineNuxtConfig({
  css: [
    '~/assets/css/admin-custom.css',
  ],
})
```

```css
/* assets/css/admin-custom.css */
.admin-sidebar {
  /* Custom sidebar styles */
}

.admin-table {
  /* Custom table styles */
}
```

## Complete Example

```typescript
// nuxt.config.ts
export default defineNuxtConfig({
  modules: ['@nuxt/ui', '@websideproject/nuxt-auto-api', '@websideproject/nuxt-auto-admin'],

  autoAdmin: {
    prefix: '/admin',

    branding: {
      title: 'Acme Corp Admin',
      logo: '/acme-logo.svg',
      favicon: '/admin-favicon.ico',
    },

    permissions: {
      unauthorizedButtons: 'disable',
      unauthorizedSidebarItems: 'hide',
    },

    features: {
      bulkActions: true,
      search: true,
      filters: true,
      export: true,
      import: false,
      auditLog: false,
    },

    middleware: 'admin-only',
  },
})
```

```typescript
// app.config.ts
export default defineAppConfig({
  ui: {
    primary: 'indigo',
    gray: 'neutral',
  },
})
```
